Hi all,

The Gazebo team is going to stop producing `.deb` packages for the **armhf** (32-bit ARM hard-float) architecture. Going forward, the supported Debian/Ubuntu architectures for Gazebo binaries are **amd64** and **arm64**.

### [](https://discourse.ros.org/t/dropping-armhf-32-bit-arm-binary-packages-for-gazebo/58156#p-118088-why-1)Why

*   The ARM platforms Gazebo users actually run on (Raspberry Pi OS, NVIDIA Jetson, ARM cloud instances) all ship 64-bitimages today, and new ARM Cortex cores have been 64-bit only since 2023.
*   Some upstream distributions are winding down their armhf ports, and key Gazebo dependencies such as DART do not support 32-bit targets.
*   Official ROS 2 binaries are only available for amd64 and arm64.
*   armhf builds consume buildfarm capacity, delay releases when their builders fail.

### [](https://discourse.ros.org/t/dropping-armhf-32-bit-arm-binary-packages-for-gazebo/58156#p-118088-what-changes-2)What changes

*   armhf is considered end-of-life across all Gazebo releases, including the currently supported ones (Fortress, Harmonic, Ionic, Jetty), in the same way an Ubuntu release reaches EOL. No new armhf packages will be published after next Monday 21st of September 2026.

*   armhf packages already published on [packages.osrfoundation.org](http://packages.osrfoundation.org/) remain available but will not receive further updates.

*   Building Gazebo from source on armhf may still work, but it is neither supported nor tested by the team.

Our release documentation already noted that the amd64/arm64/armhf combination may not be available for every Ubuntu/Debian/Gazebo release; this makes it official for armhf.

If you depend on Gazebo armhf packages, please reply here or comment on the tracking issue:

[github.com/gazebo-tooling/release-tools](https://github.com/gazebo-tooling/release-tools/issues/1548)

#### [Deprecate the armhf (32 bits ARM) .deb binary production](https://github.com/gazebo-tooling/release-tools/issues/1548)

 opened Sep 4, 2026

[![Image 7](https://us1.discourse-cdn.com/flex022/uploads/ros/original/3X/c/1/c15322d5418a3730bfb8286c8350b30f25489296.jpeg) j-rivero](https://github.com/j-rivero)

armhf (32-bit ARM hard-float) has become an obsolete target for Gazebo. The AR[…](https://discourse.ros.org/t/dropping-armhf-32-bit-arm-binary-packages-for-gazebo/58156)M platforms our users actually run on — Raspberry Pi OS, Jetson, and the ARM cloud instances used in CI -- all ship 64-bit arm64 images today, and some upstream distributions are winding down their armhf ports (like Fedora). New Cortex processors are 64bits only (since 2023) although they support 64bits since much earlier (since around 2016). Some of our main dependencies do not support 32 bits, like dart. Meanwhile armhf continues to consume buildfarm capacity, slows down releases when its builders fail, and adds a platform we cannot meaningfully test. We therefore propose deprecating armhf for Gazebo .deb packages and dropping it from future releases, keeping amd64 and arm64 as the supported Debian/Ubuntu architectures.
