Hi, i have developed [mppi_controller_cuda](https://github.com/datledoan/mppi_controller_cuda), a CUDA-accelerated MPPI (Model Predictive Path Integral) local planner, built on the [MPPI-Generic](https://github.com/ACDSLab/MPPI-Generic) framework and based on [nav2_mppi_controller](https://github.com/ros-navigation/navigation2/tree/main/nav2_mppi_controller).

 Repo: [GitHub - datledoan/mppi_controller_cuda: CUDA-accelerated MPPI controller for ROS · GitHub](https://github.com/datledoan/mppi_controller_cuda)

Two branches:

*   [`noetic`](https://github.com/datledoan/mppi_controller_cuda/tree/noetic) — ROS1, works with `move_base` and `move_base_flex`.
*   [`jazzy`](https://github.com/datledoan/mppi_controller_cuda/tree/jazzy) — ROS2 Jazzy / Nav2, drop-in `controller_server` plugin.

## post by datledoan 12 hours ago

[![Image 11](https://sea2.discourse-cdn.com/flex022/user_avatar/discourse.openrobotics.org/datledoan/48/29854_2.png)](http://discourse.ros.org/u/datledoan)

[datledoan](http://discourse.ros.org/u/datledoan)

[12h](http://discourse.ros.org/t/mppi-controller-cuda-cuda-accelerated-mppi-local-planner-for-ros1-ros2/57260/2 "Post date")

**Benchmark** (RTX 2050, AMD Ryzen 5 5500H, [turtlebot3](https://github.com/datledoan/turtlebot3) burger in Gazebo — real `move_base_flex`/`controller_server` CPU usage while actively navigating a goal, 5 runs × 50 samples each, same critic set/compute cost on both sides):

**noetic (ROS1):**

| Controller | CPU usage (of 1 core) |
| --- | --- |
| [mppi_controller_ros](https://github.com/datledoan/mppi_controller_ros) (CPU) | 33.9% ± 0.6 |
| [mppi_controller_cuda](https://github.com/datledoan/mppi_controller_cuda/tree/noetic) (GPU) | 21.9% ± 0.2 |

~35% less CPU load with the GPU plugin.

**jazzy (ROS2/Nav2):**

| Controller | CPU usage (of 1 core) |
| --- | --- |
| nav2_mppi_controller (CPU) | 49.4% ± 1.4 |
| [mppi_controller_cuda](https://github.com/datledoan/mppi_controller_cuda/tree/jazzy) (GPU) | 35.7% ± 0.7 |

~28% less CPU load with the GPU plugin.
