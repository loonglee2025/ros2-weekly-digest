# ROS2 Weekly Digest - 2026-07-20

**时间范围：** 2026-07-13 至 2026-07-19（上一自然周）  
**总判断：** 本周 ROS 2 的主旋律是「治理结构正在重塑、执行器与中间件继续收敛、物理 AI 与机器人描述抽象成为新热点」。核心代码层 rclcpp 正式废弃实验性 EventsExecutor，同时 Client Library WG 在优化 Fast RTPS 类型支持内联；治理层面 ROS PMC 围绕项目 Leader 角色缺位和 OMG IDL 与 ROS IDL 的割裂展开讨论；生态层面 Nav2 + SAM3 语义导航、多个 LLM  grounding 工具、机器人描述 IR 以及 RTPS 安全 watchdog 成为高关注社区项目。整体信号偏向「承上启下」：Lyrical 的新 executor 故事在收尾，Bazel/Physical AI/ROS 与 AI 的边界开始升温。

## 本周关键信号

1. **rclcpp 正式废弃实验性 EventsExecutor，EventsCBGExecutor 转正并支持可重入回调组**
   - 发生了什么：rclcpp 本周合并 PR #3192，将实验性 `EventsExecutor` 标记为 deprecated；同时 PR #3178 给 `EventsCBGExecutor` 增加了可重入回调组（reentrant callback group）支持，并补了并发测试。PR #3190 修复 ComponentManager 在移除节点时未检查 executor 关联的崩溃问题。
   - 为什么值得关注：这是 rclcpp executor 架构的明确收敛信号——`EventsCBGExecutor` 成为非实验性的多线程事件驱动执行器，而旧的 EventsExecutor 将逐步退出。对使用事件执行器的代码意味着需要迁移。
   - 影响哪一层：所有依赖事件驱动 executor 或自定义 component manager 的 ROS 2 应用；Lyrical/Rolling 用户首当其冲，Jazzy/Humble 的 backport 策略需关注。
   - 下一步盯什么：废弃宏是否在后续版本升级为删除，以及 `EventsCBGExecutor` 的 benchmark 是否进入官方性能基线。

2. **ROS PMC 讨论项目 Leader 角色缺位与拆分：治理进入「后全职 Leader」时代**
   - 发生了什么：7 月 14 日 PMC 会议纪要显示，到 7 月 13 日截止日期无人自荐 ROS Project Leader。PMC 讨论将原本全职的 Leader 角色拆分为 Secretary、Triage Lead、Rosdistro Lead、Security Officer 等更窄的职务，并通过非货币激励（OSR 会员资格、ROSCon 差旅、专属邮箱/Claude 订阅）吸引继任者。
   - 为什么值得关注：自 clalancette 离职后，ROS 的核心技术决策、发布节奏和社区协调正从「单一全职技术领袖」转向「委员会 + 轮值子角色」。这会影响 PR 合并、版本发布、安全响应的速度和一致性。
   - 影响哪一层：整个 ROS 2 生态的治理节奏。开发者应预期 PMC 决策更依赖异步投票和子角色分工，紧急问题可能需要更明确的升级路径。
   - 下一步盯什么：关注 mjcarroll 承诺的 Project Leader handbook 是否发布，以及子角色提名是否开启。

3. **PMC 重提「OMG IDL vs ROS IDL」的选型债务，建议走低成本回退方案**
   - 发生了什么：sloretz 在 PMC 提出，Crystal 时期将 ROS 消息 canonical 表示从 ROS IDL 改为 OMG IDL，但社区实际仍只用 ROS IDL 编写消息。这导致 Python 生成类的 `get_fields_and_field_types()` 返回 OMG IDL 语法，与用户直觉不符。PMC 建议 ros2/rosidl_python#262 采用「新增 ROS IDL 方法」的最小改动方案，而非整体翻转 rosidl_adapter。
   - 为什么值得关注：这是一个长期积累的技术债务。如果处理不好，会影响 Python 侧消息 introspection、rosbridge 行为、工具链一致性。最小改动方案虽然安全，但保留了双重表示，可能继续造成认知分裂。
   - 影响哪一层：rosidl、代码生成、rosbridge、Python 工具链；对编写自定义消息和调试字段类型的开发者影响最直接。
   - 下一步盯什么：rosidl_python#262 是否被合并，以及是否会提供官方文档说明何时使用哪种表示。

4. **Nav2 + SAM3 在 AMD Strix Halo 上实现文本提示的语义导航，边缘端 5-10 Hz**
   - 发生了什么：Steve Macenski（Nav2 维护者）在 Discourse 分享与 AMD 的合作：利用 Meta SAM3 的文本提示分割能力，在 AMD Strix Halo（Ryzen AI Max+ 395）上实现无需重新训练的语义导航，与 Nav2 costmap 和规划栈集成，可动态提示「floor」「sidewalk」「pallet」等类别，边缘运行 5-10 Hz。
   - 为什么值得关注：这是 foundation model 与 ROS 2 导航栈结合的可落地样本。它把语义信息从「离线标注/固定类别」推进到「运行时自然语言提示」，对仓库物流、户外移动机器人、施工场景有现实意义。
   - 影响哪一层：Nav2 应用层、语义 costmap、边缘 AI 部署（尤其是 AMD/ROCm 生态）。
   - 下一步盯什么：代码和教程是否进入 docs.nav2.org，以及是否支持 NVIDIA Jetson 等其它边缘平台的对比 benchmark。

5. **Bazel 构建 ROS 接近全绿：静态可执行文件 4.7 MB、单核缓存构建 12-15 分钟**
   - 发生了什么：andrew_symington 在 PMC 更新中称，Bazel 构建 ROS up to perception（`ros2/ros_up_to_perception`）仅剩 macOS 上 mimick 与 Darwin sandbox 的交互问题，其它平台已接近全绿。在 warmed cache 下单核构建仅需 12-15 分钟，且可将 ROS 节点静态链接为 4.7 MB 的可移植二进制文件。
   - 为什么值得关注：Bazel 对 ROS 2 的 hermetic、可复现构建一直是社区痛点。4.7 MB 静态二进制对边缘部署、容器分发、供应链安全都有吸引力。里程碑达成后计划成立 Bazel Working Group 并在 ROSCon/BazelCon 展示。
   - 影响哪一层：构建系统、CI/CD、边缘部署、容器镜像裁剪；NVIDIA 已表示有兴趣加入该 WG。
   - 下一步盯什么：macOS 问题的修复 PR、Bazel WG 的正式成立公告、Lyrical June 8 发布的目标是否能达成。

6. **社区安全/工具热点：RoboShield RTPS watchdog、ros2_lingua LLM grounding、DDSConfig-Optimizer 支持 CycloneDDS**
   - 发生了什么：
     - RoboShield：用 Rust 实现的带外 RTPS 安全 watchdog，可在 NanoPi 等双网口设备上嗅探 DDS 包，检测未授权节点、topic 泛洪，平均包处理 ~1.36 μs，不依赖 SROS2 证书。
     - ros2_lingua：让机器人在运行时向注册中心自注册 capability，LLM 只调用实际存在且可达的 action/service，并带校验层与重试恢复。
     - ROS2-DDSConfig-Optimizer：高通 QRB-ROS 出品的 AI 自动调参工具，从仅支持 Fast DDS 扩展为支持 CycloneDDS，下一步考虑 Zenoh。
   - 为什么值得关注：这三条分别对应 ROS 2 在 production security、AI agent 落地、DDS 性能调优三个方向的社区创新。它们都不是官方仓库变化，但代表了 ROS 2 在真实部署中必须补的课。
   - 影响哪一层：安全/网络运维、AI agent 集成、DDS 性能敏感应用。
   - 下一步盯什么：RoboShield 是否进入 SROS2 互补生态讨论；ros2_lingua 是否加入 ros2/cli 相关的工具链；DDSConfig-Optimizer 的 Zenoh 支持进展。

## 核心框架更新

- **rclcpp**：
  - 废弃实验性 `EventsExecutor`（#3192），建议迁移到 `EventsCBGExecutor`。
  - `EventsCBGExecutor` 支持可重入回调组（#3178），并补充并发测试，意味着多线程事件执行器可以更安全地处理递归/重入回调。
  - `ComponentManager` 修复移除节点前未检查 executor 关联的崩溃（#3190）。
  - 新增 transient-local 投递测试，针对 unbounded uint8 消息（#3195）。

  - skye.galaxy 修复 component manager 销毁时的 double-remove 问题，并跟进废弃 experimental events executor。
- **Accelerated Memory Transport WG**：
  - 下次会议改期，相关 RMW REP 仍在讨论中（与 OMG IDL/ROS IDL 争议存在交集）。

## 工程化观察

- **EventsExecutor 废弃 ≠ 事件驱动执行器退场**：相反，rclcpp 通过 `EventsCBGExecutor` 把事件驱动与回调组机制更紧密地结合，并支持可重入。对仍在使用 EventsExecutor 的代码，需要制定迁移计划；对新项目，应优先评估 `EventsCBGExecutor` 是否满足实时性要求。
- **ROS 治理的空窗期需要关注**：Project Leader 角色空缺、角色拆分讨论，意味着未来一段时间 ROS 2 的核心决策将更加依赖 PMC 的异步投票。如果你的团队依赖 ROS 2 的发布节奏和安全补丁，建议提前关注 PMC 会议纪要中的 rosdistro/release management 段落。
- **OMG IDL/ROS IDL 的分裂是工具链一致性的隐患**：虽然 PMC 选择最小改动方案，但长期看两种表示并存会让 introspection、代码生成、rosbridge 行为难以保持一致。团队在编写自定义消息时，应明确了解生成代码实际返回的字段名和类型名。
- **Bazel 构建 ROS 的里程碑值得提前评估**：4.7 MB 静态二进制和 12-15 分钟 warmed cache 构建，对 CI/CD 和边缘分发非常有吸引力。如果团队已有容器化/ reproducible build 需求，可以开始跟踪 Bazel WG 的成立和文档。
- **物理 AI / LLM 与 ROS 2 的边界正在快速扩张**：从 Nav2+SAM3 语义导航、到 ros2_lingua 的 capability grounding、再到 AgenticROS 项目，LLM 与机器人执行层的结合已经从 demo 进入工具化阶段。需要关注的是这些工具如何与官方 CLI/launch/rosbridge 标准整合，而不是各自为政。
- **DDS 调优仍是无差别痛点**：DDSConfig-Optimizer 支持 CycloneDDS 的热度说明，手动调 DDS 参数仍然是 ROS 2 多机部署的普遍障碍。Zenoh 支持进入 roadmap 后，社区需要一个新的统一调参模型。

## 前沿议题

- **REP-2000 的维护状态与平台信息集中化**：社区提出 REP-2000 只更新到 Kilted，Lyrical 信息缺失。Open Robotics 回应称 REP-2000 已迁移到 reps.openrobotics.org，各发行版的平台支持信息应查看对应文档。社区仍在讨论是否需要保留一个「所有发行版一目了然」的汇总表。对开发者而言，这意味着查找平台/依赖信息需要适应新的官方入口。
- **RTPS 安全与 SROS2 的互补路径**：RoboShield 代表了「不改造现有节点、带外监控」的安全思路，与 SROS2 的「端到端证书」形成互补。未来生产部署可能同时需要 SROS2 + watchdog，或者催生新的中间件安全标准。
- **机器人描述中间层**：LinkForge 提出的 IR 思路如果得到广泛支持，可能改变 URDF/XACRO → ROS/Gazebo 工作流。当前最大挑战是说服现有工具链和标准化组织接受一个新抽象层。
- **ROS 2 与 AI 贡献的边界**：随着 ros2_lingua、AgenticROS 等项目的出现，AI 不再只是生成文档和代码，而是直接参与运行时决策。PMC 的 AI 贡献治理指南与这些运行时 AI 工具之间存在张力，需要社区明确「AI 辅助开发」和「AI 运行时组件」的不同责任边界。
